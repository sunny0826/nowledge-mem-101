A knowledge system in Nowledge Mem is useful only when it can return the right context at the moment of work. Test the whole topic with a question that needs the current state, evidence, and history.

## What you'll accomplish

<Check>
  You'll run one retrieval test, repair one weak spot, and save a lightweight maintenance procedure.
</Check>

## Your turn

<Steps>
  <Step title="Ask a question that needs the whole system">
    In Timeline, ask:

    ```text
    What is Atlas's current decision about annual planning reviews? Show the earlier decision, what changed, the supporting source, and any unresolved risk. Separate saved evidence from inference.
    ```
  </Step>
  <Step title="Trace the answer">
    Open the memories and source behind the most important claims. Confirm that the current decision is not confused with the earlier state and that the explicit Memory Link is used in the right direction.
  </Step>
  <Step title="Repair one weak spot">
    Improve one missing or ambiguous item: clarify a memory, save a verified takeaway, add a meaningful link, or correct an over-broad label. Then ask the same question again.
  </Step>
  <Step title="Save a maintenance procedure">
    Leave a small rule for future you:

    ```text
    Atlas knowledge-system check

    Once a month, ask for the current planning decision, its source, what changed, and the largest open risk. Repair one unclear memory or relationship, then stop.
    ```
  </Step>
</Steps>

## What you should see

<Check>
  Mem returns the current answer with traceable evidence and visible history. The second run is clearer because you repaired a specific gap instead of reorganizing everything.
</Check>

## Why this matters

Retrieval is the acceptance test for a knowledge system. A short, repeated check keeps the topic useful without turning maintenance into a separate project.
