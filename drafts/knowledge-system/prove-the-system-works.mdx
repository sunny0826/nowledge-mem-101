## Before you start

Keep the current decision, earlier decision, and source from the previous lessons accessible. For the fictional Atlas timeline, the October update is current. Write down the expected answer before asking Mem so you can evaluate the result independently.

## Your turn

<Steps>
  <Step title="Ask a question that needs the whole system">
    In Timeline, ask:

    ```text
    What is Atlas's current planning review cadence according to the saved records? Find the latest update and inspect earlier history where available. Show the earlier decision, reason for the change, relevant source, and open questions. Identify which record supports each claim and separate evidence from inference. If history or evidence is missing, say so.
    ```
  </Step>
  <Step title="Trace the answer">
    Open the records behind the key claims. Use this checklist for the practice case:

    | Check | Expected evidence |
    | --- | --- |
    | Current state | October update: two smaller reviews each year |
    | Earlier state | September decision: one annual review |
    | Reason for change | October update: useful dependencies found, but too much preparation |
    | Source boundary | The August retrospective supports trying earlier coordination; it does not establish the later pilot result |
    | Still open | Review months and a preparation limit |

    If the answer describes the Memory Link, compare that explanation with the saved relation. A plausible answer alone does not prove it used the link.
  </Step>
  <Step title="Repair one weak spot">
    Match the repair to the failure: a wrong cadence needs the dated update; a missing source needs a usable reference; an overstated conclusion needs its limit restored. Then repeat the same question and check the repaired point. If every check passes, record that result and continue.
  </Step>
  <Step title="Save a maintenance procedure">
    Save this procedure in **Timeline**, adapting it to your topic and pressing Enter:

    ```text
    Atlas knowledge-system check

    At my monthly review, ask for the current planning decision, its source, what changed, and the largest open question. Compare the answer with the records. If a check fails, repair that point and repeat the question. Record the check date and result.
    ```

    Find the saved procedure by name so you can use it at your next review.
  </Step>
</Steps>

## What you should see

<Check>
  The answer passes the checks against the saved records, or clearly identifies what is missing. Any repaired point passes when rechecked, and the maintenance procedure is saved and findable.
</Check>

## Why this matters

Retrieval is the acceptance test for a knowledge system. A short, repeated check keeps the topic useful without turning maintenance into a separate project.
