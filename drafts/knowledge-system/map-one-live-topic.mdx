## Before you start

Choose a topic with a few related memories in the same Space. Keep Mem running. The goal is to inspect existing knowledge before adding more.

<Accordion title="Practise with a fictional topic">
  If you do not have a topic ready, save each of these as a separate memory in **Timeline**, pressing Enter after each. These dates belong to the fictional course timeline.

  ```text
  Atlas annual review decision — fictional practice, 2026-09-01
  Atlas approved one cross-team planning review per year, starting with a September pilot. The goal is to find shared dependencies earlier using existing quarterly notes. Success criteria are not yet agreed.
  ```

  ```text
  Atlas planning learning — fictional practice, 2026-08-20
  A quarterly review found a shared dependency after team plans were committed. Earlier cross-team discussion may help, but its effect has not been tested.
  ```

  ```text
  Atlas review preparation — fictional practice, 2026-09-01
  Before the review, collect existing team plans, mark shared dependencies, and name an owner for each open dependency. Record preparation time so the team can assess the workload.
  ```
</Accordion>

## Your turn

<Steps>
  <Step title="Choose one topic that will keep changing">
    Name a question you expect to revisit, such as "How should Atlas run and evaluate cross-team planning reviews?" Keep the boundary narrow enough to inspect a few memories.
  </Step>
  <Step title="Browse the topic in the Library">
    Open **Library → Wiki** and choose a relevant topic. Follow its summary to an entity and an underlying memory. Check the memory itself before treating the summary as current.

    If no useful Wiki topic appears, use memory search for "Atlas planning" and open the matching records. Wiki topic detection is optional for this audit; you can complete it with search alone.
  </Step>
  <Step title="Name what is present and missing">
    Identify the current decision, one supporting record, and one unanswered question. Note record names and dates so you can return to them. If the records disagree, preserve that as a gap rather than choosing a winner by date alone.
  </Step>
  <Step title="Save the audit in Timeline">
    Adapt this audit to the records you actually found. Paste it into **Timeline** and press Enter:

    ```text
    Atlas planning knowledge audit — fictional practice

    Scope: How Atlas runs and evaluates its annual planning review.
    Current decision: one review per year, starting with a September pilot (Atlas annual review decision, 2026-09-01).
    Existing evidence: one late-discovered dependency (Atlas planning learning, 2026-08-20); this does not yet show the review will help.
    Preparation record: Atlas review preparation, 2026-09-01.
    First gap: no agreed success criteria for the pilot.
    ```

    Ask "What is the first gap in the Atlas planning knowledge audit?" and check that Mem returns the missing success criteria.
  </Step>
</Steps>

## What you should see

<Check>
  You can find the audit and open the records it names. It defines the topic and identifies a gap without treating an untested idea as an established result.
</Check>

## Why this matters

A useful boundary keeps the system focused on a recurring question. It gives new memories and sources a reason to belong without forcing you to design a complete hierarchy first.
