## Before you start

Have the brief, lesson 3 checkpoint, and lesson 4 draft ready. Decide what you accept and what still needs review.

## Your turn

<Steps>
  <Step title="Decide what to keep in the checkpoint">
    Keep the accepted decision, the draft or its location, unresolved evidence, and the next action. Check every "needs evidence" marker before calling the draft ready to publish.
  </Step>
  <Step title="Update the handoff checkpoint">
    Open **Memories**, search for `Atlas landing page handoff checkpoint`, and open the matching memory from lesson 3. Edit it to match the current task state using this fictional example:

    ```text
    Atlas landing page handoff checkpoint

    Accepted: keep "Try Atlas" as the single call to action.
    Completed: the hero and section four drafts are written.
    Status: ready for review, not approved for publication. Section four still has a "needs evidence" marker.
    Draft: add the actual file name or document link here.
    Next step: ask the product owner for a verified example, then revise and review section four before publishing.
    ```

    Add the accepted copy, or record its actual file name or document link. Confirm the next tool can open it, then save.
  </Step>
  <Step title="Test the restart point">
    In a fresh session with a connected AI, ask:

    ```text
    Search Nowledge Mem for the Atlas landing page handoff checkpoint. What is complete, what still blocks publication, where is the draft, and what is the next action?
    ```

    If it repeats the old action, reopen the checkpoint and confirm the edit was saved. Clarify the status, then retry.
  </Step>
</Steps>

## What you should see

<Check>
  The AI finds the draft and says that evidence review comes next. It does not restart completed drafting or describe the page as ready to publish.
</Check>

## Why this matters

Closing the loop keeps the handoff checkpoint current. The next session can continue from the latest task state instead of an outdated next action.
